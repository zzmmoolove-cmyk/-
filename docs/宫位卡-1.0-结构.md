## 1. 分层架构与责任边界

```
L0 排盘引擎（iztro，确定性）
   └ 十二宫、星曜、庙旺、生年四化、宫干支、长生十二神、大限
L1 星曜档案库（本项目的「数据库备份」）
   └ 只存与盘无关的本体：五行阴阳、等级、化气、象义、根性、四化/自化、
     十二宫投射、组合提示、用星建议
L2 规则引擎（可计算、可解释）
   └ 五行生克、庙旺力度、四化/自化、飞化、吉煞比、五行链、卡点规则
L3 宫位卡（结构化数据 + 可读文本）
L4 Prompt 分发（复制给通用大模型，不依赖 API Key）
L5 AI 直连（可选）：用户自己的 Key，浏览器直连
L6 运限叠加（v2）：大限/流年引动，分区「本命底色 / 运限引动」
```

**关键原则**

1. **能算的不写死**：庙旺、生年四化、宫干、大限由 L0 提供；资料库不重复存储，避免数据打架。
2. **写死的必须可追溯**：星曜档案带 `source` 与 `tier`；报告每条结论带 `evidence`。
3. **缺数据就标注**：杂曜无庙旺（iztro 不提供）时按中性 0.8 计，并在「数据缺口」明说，不硬编。
4. **结论不宿命**：只输出「能量关系 + 发挥方向 + 风险 + 动作」，不预测具体事件。

## 2. 星曜档案：`StarProfile` v1.0

### 2.1 字段

| 字段 | 说明 | 示例（武曲） |
| --- | --- | --- |
| `name` / `aliases` | 名称与别称 | 武曲 / 财星、将星、寡宿 |
| `wuxing` / `yinyang` | 五行阴阳 | 金 / 阴 |
| `grade` | 甲/乙/丙/丁级 | 甲 |
| `category` | 主星/吉星/煞星/禄存/天马/桃花/杂曜/神煞 | 主星 |
| `doufen` / `huaqi` | 斗分、化气 | 北斗 / 化气为财 |
| `essence` | 一句话本质（五行+化气+气质+课题） | 阴金的价值尺度与决断 + 财星将星 + 刚直孤克的执行者 |
| `keywords` | 3–5 个核心象义 | 财星、将星、刚毅、务实、孤克 |
| `root` | 五行根性推导（为什么是这些象） | 阴金主从革、肃杀、主义…… |
| `body` | 身体对应 | 肺、大肠、牙齿骨骼、呼吸道 |
| `positive` / `negative` | 正负面各 2–3 条 | — |
| `sihua` | 本星四化含义（禄/权/科/忌） | 武曲化忌：财务易波折…… |
| `zihua` | 自化能量走向（外泄/内收） | 自化忌：利剑向内收刃…… |
| `palaces` | 十二宫投射，每宫一句 | 财帛：财星主场，靠专业实干得财 |
| `combos` | 固定组合提示（含吉/慎/条件性） | +文昌：文将 |
| `use` | 适合领域/风险/修正/一句话 | — |
| `tier` | `full` 手工整理 / `lite` 单行待扩写 | full |
| `source` | 口径与出处说明 | 三合派常用口径 |

### 2.2 覆盖

- 67 颗：14 主星 + 六吉六煞 + 禄存天马 + 四桃花 + 常见杂曜。
- 40 颗完整（含十二宫投射），27 颗简版（会显示「待扩写」）。
- 未收录的星：自动回退到旧版 `STAR_KB`，再不行按杂曜显示「资料待补」。
- **导出备份**：顶部「导出星曜库」→ JSON（`schema: ziwei-star-profile/1.0`），可纳入版本管理或二次加工。

### 2.3 为什么十二宫投射只写「一句」

宫位卡需要的是「这颗星在这个宫的场景化表现」。一句投射 + 同宫联动 + 庙旺 + 四化，已经足够组装；写成一整段反而会掩盖联动。真正展开由 Prompt 交给大模型完成，且必须引用本宫数据。

## 3. 宫位卡：`PalaceSnapshot` 十节

| 节 | 内容 | 数据来源 |
| --- | --- | --- |
| 元信息 | 命主/身主/五行局/身宫/长生/大限 | L0 |
| 一、宫位定位 | 领域、关注点、权重、吉煞比 | `palaces.ts` + 规则 |
| 二、本宫星曜 | 星名/类别/五行/庙旺/生年四化/自化/本宫表现 | L0 + L1 + 规则 |
| 三、同宫联动 | 以主星为主体，逐对「关系 + 判词 + 吉煞修正」 | L2 |
| 四、三方四正 | 对宫 0.6、三合 0.45，各带吉煞分与联动 | L2 |
| 五、五行链 | 长度 ≥3 的顺生链 / 克链 | L2 |
| 六、四化 | 生年四化落本宫、宫干自化、宫干飞化去向 | L2 |
| 七、卡点与策略 | 规则命中：依据 → 影响 → 解法 → 动作 | L2 规则表 |
| 八、用星建议 | 每星适合/风险/修正/一句话 | L1 |
| 九、数据缺口 + 自检 | 缺什么、按什么口径处理、自检项 | 规则 |

### 3.1 权重

```
本宫 1.0（定质地） ＞ 对宫 0.6（正照，外部环境最直接） ＞ 三合 0.45（斜照，格局与资源）
```

- 先本宫后三方：本宫决定「是什么」，会照决定「在什么环境里」。
- 权重是常量，写在 `WEIGHTS`，后续可做成设置项。

### 3.2 吉煞比（不是「吉煞分」）

```
吉煞比 =（吉星权重 − 煞星权重）/（吉星权重 + 煞星权重）∈ [-1, 1]
吉星权重 = Σ（吉星力度 × 宫位权重），煞星同理
力度 = 庙1.7 / 旺1.44 / 得·利1.18 / 平0.92 / 不·陷0.66；无庙旺按 0.8
```

为什么不用加总：吉星数量天然多于煞星，加总会系统性偏吉。用比值只描述**环境强弱**，且明确写着「不作吉凶断言」。

## 4. 规则引擎 v1.0

### 4.1 五行关系

`生我 / 同我 / 我生 / 我克 / 克我`，由两颗星的五行直接判定；判词按**本星五行 × 关系**取象（5×5 = 25 条），换星不换框架。

判词示例（金）：
- 生我：土生金，得根得助，资源与名分托底。
- 同我：金遇金，锋利加倍，专业更硬，也更孤更冲。
- 我生：金生水，价值流通为人脉与现金流。
- 我克：金克木，能修剪塑形，成器但劳心。
- 克我：火克金，受炼——旺则成器，弱则刑伤。

再叠加吉煞修正：吉星生我大吉、煞星同我增凶、吉星克我磨练、煞星克我刑伤。

### 4.2 四化与自化

- 十天干四化表（与 iztro 一致）：甲廉破武阳……癸破巨阴贪。
- **生年四化**：`star.mutagen`（L0 提供），代表先天「进货」。
- **自化**：本宫宫干引动本宫星曜 → 能量外泄或内收；星曜有专门说明则用，否则用通用语义。
- **飞化**：本宫宫干引动他宫星曜 → 输出「星 → 目标宫」，形成跨宫关系。

### 4.3 卡点规则（可扩展）

| id | 触发 | 严重度 | 说明 |
| --- | --- | --- | --- |
| `empty-palace` | 本宫无任何星 | 低 | 借对宫 |
| `no-major` | 有星无主星 | 中 | 缺主轴 |
| `sha-in-palace` | 本宫有煞星 | 中/高 | 摩擦与代价 |
| `weak-main` | 主星陷/不 | 中 | 主星无力 |
| `weak-auspice` | 吉星陷/不 | 中 | 助力不足 |
| `zihua-ji` | 自化忌 | 高 | 能量内收 |
| `natal-ji` | 生年忌落宫 | 中 | 先天课题 |
| `lu-ji-same` | 生年禄 + 自化忌同宫 | 中 | 得中有失 |
| `opposite-sha` | 对宫吉煞分 < −0.8 | 中 | 对宫冲照 |

每条卡点固定四段：**依据 / 影响 / 解法 / 动作**。动作必须是一个「本周可做」的小步骤，避免停在道理层。

## 5. Prompt：为什么这样写

复制给通用大模型的 Prompt 由四段组成（实现见 `buildPalacePromptText`）：

1. **角色与边界**：不做宿命断言、不预测事件、不给医疗/法律/投资建议。
2. **8 条解构原则**：宫位是场景滤镜、本宫优先、五行只定关系、庙旺是力度、自化是方向、五行口诀、缺数据标中性、必须落到动作。
3. **输入数据**：完整的宫位卡文本（十节全给）。
4. **输出格式 + 质量红线**：十二节输出（含「意象图画」「化煞为权」）、逐项自检、禁止套用命宫、禁止虚构会照/庙旺。

> 「意象图画」与「化煞为权」不在本地硬编：前者容易变成模板抒情，后者需要结合具体煞忌与场景判断。它们留在 Prompt 的输出结构里，由大模型基于本卡数据生成，并受「元素必须对应星曜」「路径→前提→标志」的格式约束。

**设计取舍**

- 不把「结论」预先写好再让模型润色——那会变成 AI 复读机；给数据 + 结构，让模型做场景化推理。
- 结构与 UI 一致：用户看到的卡，和模型产出的卡，是同一套字段，便于对比与回填。
- 不依赖 API Key：任何通用大模型都能用，降低使用门槛。

## 6. 十二宫延展

- 生成器与宫位无关，`buildPalaceSnapshot(astrolabe, palaceName)` 对十二宫通用。
- 顶部「十二宫索引」：每宫显示主星、吉煞比、卡点数，一点即切，形成全盘扫描。
- 建议阅读顺序（与对话一致）：**命身定根 → 三方四正定路 → 六亲定网 → 功能定底**；身宫所在宫、煞忌重的宫可提前。
- 每个宫位都能独立「复制 Prompt」，因此十二宫 = 十二张可外发的卡，不依赖本应用。

## 7. 数据缺口与诚实原则

v1.0 明确标注的缺口：

1. 杂曜无庙旺（iztro 不提供）→ 按中性 0.8，卡片上写「亮度未提供」。
   > 参考稿里给过「华盖平、封诰利、蜚廉利」这类取值，但各派口径不一、引擎也不提供；v1.0 选择**不硬编**，待 v1.1 做成「流派庙旺表 + 用户覆盖」后再补。
2. 部分神煞无四化 → 显示「本星不参与四化」。
3. 本命盘静态，不含大限/流年/流曜 → 卡片末尾固定声明。
4. 未收录星曜 → 回退旧知识库，仍无则「资料待补」。
5. 会照只算三方四正，不含夹宫/拱照的细部 → v2 补。

> 宁可少说一句，也不编一句。这是这个产品与「排盘后一头雾水」的命理软件的第一道分水岭。

## 8. 产品优化方向（结合「看见关系、发现卡点、应对策略」）

### 方向一：从「排盘工具」变成「提问机」——每张卡必须产出一个动作

现状：卡片已经给出「依据 → 影响 → 解法 → 动作」。
下一步：把「动作」抽出来做成**行动清单**（可勾选、可设定日期、可回看），并允许用户标记「这条不准」。命理产品最大的浪费，是用户看完点头、出门就忘。

### 方向二：关系图谱——让「命盘在表达的关系」变成可点的图

现状：五行链、三方四正、飞化都已经是结构化数据。
下一步：用 SVG 画「宫—星」二部图：节点是十二宫与星曜，边是生克/三合/对宫/飞化；点边出判词，点星出档案。**这是本产品最该有的差异化界面**——大众软件给一张盘，我们给一张「关系地图」。

### 方向三：追问链——把「看不懂」变成「三个可点的追问」

现状：用户拿到卡，可能仍不知道下一步问什么。
下一步：每条结论旁挂 3 个追问（为什么？和我命宫什么关系？怎么破？），点击即生成对应 Prompt 并复制。把「会提问」这件专业能力，做成按钮。

### 方向四：时间轴——本命底色与运限引动必须分区

现状：v1.0 只做本命。
下一步：叠加大限/流年四化与流曜后，报告自动分两栏：「本命底色（不变）」与「运限引动（今年）」，并标注哪条结论是被引动的。**不分区的运限解读，是用户混乱的主要来源。**

### 方向五：校准与出处——让结论可被验证，而不是被相信

现状：每条有 `evidence` 与数据来源，但无用户反馈。
下一步：用户可标记「准/不准/已发生」，形成个人语料；再把古籍原文接成 RAG，让关键判断能点开看原文。长期看，这是「可信度」的护城河。

> 备选：分享长图（咨询场景）、双人合盘（关系场景）、名人盘对照（学习场景）。优先级低于前五个。

## 附录 A：盘面批注层（v1.0.1）

**交互**：悬停 → 一句话批注（深色气泡，不挡点击）；点击 → 弹层（星曜走完整档案，其余走概念说明）。

**覆盖范围**

| 盘面元素 | 批注 | 点击 |
| --- | --- | --- |
| 星曜（主/辅/杂曜） | 五行阴阳 · 庙旺 · 生年四化 · 一句话本质 | 完整星曜档案 |
| 庙旺字（庙/旺/得/利/平/不/陷） | 力度与发挥状态一句话 | 庙旺说明（力度，不改性质） |
| 四化字（禄/权/科/忌） | 能量方向一句话 | 四化说明（方向，受庙旺放大） |
| 宫名 | 宫干支 · 身宫 · 长生 · 宫位一句话 | 切到该宫位卡并滚动到位 |
| 长生十二神 | 气机状态一句话 | 概念说明 |
| 博士/岁前/将前十二神 | 神煞一句话 | 概念说明 |
| 宫干支 | 天干五行 · 地支气质 | 干支说明 + 本宫宫干四化 → 目标宫 |
| 大限 / 小限 | 运限一句话 | 运限说明 |
| 运限流曜（运昌/流禄等） | 层位 + 本命星 + 一句话引动 | 派生档案（说清“不是新星”） |
| 命主 / 身主 / 五行局 | —（直接点） | 对应星曜档案 / 五行局说明 |

**运限流曜**：运/流/月/日/时五层 × 魁钺昌曲禄羊陀马鸾喜十颗 = 50 个名字，全部由本命星派生（`flow` 元数据）。派生档案只讲「这一层哪一宫被什么主题引动」，不复制十二宫投射、不参与本命吉煞比，换限即失效。

**边界**：中心四柱、动态宫名暂未接入——没有稳定知识源就不硬编。批注只做「提示」，不做结论；结论仍在宫位卡。

**为什么值得做**：用户看盘的第一反应是「这个字是什么」，而不是「帮我生成一份报告」。先让每个字可问，再谈分析深度。
